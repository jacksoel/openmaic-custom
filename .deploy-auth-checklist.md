# Post-Deploy Auth Verification Checklist

Run these checks after every deploy that touches `middleware.ts`, `lib/auth.ts`, `lib/server/auth-db.ts`, or `.env.local` auth variables.

## 1. Environment Sanity

Verify these values match the intended environment before restarting:

| Variable | Expected | Check |
|----------|----------|-------|
| `AUTH_ENABLED` | `true` (production) / `false` (dev) | `grep ^AUTH_ENABLED= .env.local` |
| `NEXT_PUBLIC_AUTH_ENABLED` | Must match `AUTH_ENABLED` | `grep ^NEXT_PUBLIC_AUTH_ENABLED= .env.local` |
| `BETTER_AUTH_SECRET` | Non-empty, ≥32 chars | `grep ^BETTER_AUTH_SECRET= .env.local \| cut -d= -f2 \| wc -c` |
| `BETTER_AUTH_URL` | Full origin URL (e.g. `https://maic.coachingthegist.com`) | `grep ^BETTER_AUTH_URL= .env.local` |
| `NEXT_PUBLIC_APP_URL` | Must match `BETTER_AUTH_URL` origin | `grep ^NEXT_PUBLIC_APP_URL= .env.local` |
| `SECURE_COOKIES` | `true` in production (HTTPS) | `grep ^SECURE_COOKIES= .env.local` |
| `ALLOWED_EMAIL_DOMAINS` | Comma-separated list, or empty for allow-all | `grep ^ALLOWED_EMAIL_DOMAINS= .env.local` |
| `TRUSTED_ORIGINS` | Optional; defaults to `NEXT_PUBLIC_APP_URL` + localhost | `grep ^TRUSTED_ORIGINS= .env.local` |
| `ACCESS_CODE` | Optional; if unset, ACCESS_CODE flow is skipped | `grep ^ACCESS_CODE= .env.local` |
| `AUTH_ADMIN_EMAIL` | Admin seed email (only used on first boot) | `grep ^AUTH_ADMIN_EMAIL= .env.local` |
| `AUTH_ADMIN_PASSWORD` | Admin seed password (only used on first boot) | `grep ^AUTH_ADMIN_PASSWORD= .env.local` |
| `RESEND_API_KEY` | Required for password reset emails; if unset, reset URLs logged to stdout | `grep ^RESEND_API_KEY= .env.local` |

**Docker build note:** `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL` must be passed as build args (not just runtime env) because they're baked into the Next.js client bundle at build time. Verify `docker-compose.yml` has `build.args` for both.

**Auth seed note:** Seed env vars (`AUTH_ADMIN_EMAIL`, `AUTH_ADMIN_PASSWORD`, `AUTH_ADMIN_NAME`) only create the admin on first boot. If the admin already exists, the seed is skipped and the password in `.env.local` is ignored. Changing an existing admin password requires a direct DB update or a password reset.

## 2. Auth DB Directory

On fresh volumes or after `docker compose down -v`:

- [ ] Startup logs show `[Auth] Extension database initialized at /app/data/auth/auth.db`
- [ ] Startup logs show `[Auth] better-auth initialized` (not an SQLITE_CANTOPEN error)
- [ ] `getDb()` now calls `mkdirSync({ recursive: true })` before opening SQLite — if you see a missing-directory error, the fix didn't apply

## 3. ACCESS_CODE Flow (if `ACCESS_CODE` is set)

Only applicable when `ACCESS_CODE` is configured. Skip if auth-enabled mode is active.

- [ ] **Malformed cookie:** Send `Cookie: openmaic_access=garbage` to a protected page → should reject or show access-code modal
- [ ] **Mutated signature:** Take a valid `timestamp.signature` token, change one hex char in the signature → should be rejected
- [ ] **Expired timestamp:** Create a token with a timestamp older than 7 days → should be rejected
- [ ] **Valid token:** Use a properly HMAC-signed token → should pass and return page content

## 4. Auth-Enabled (Session) Flow

- [ ] **Unauthenticated page request:** `curl -sI http://localhost:3001/dashboard` → 307 redirect to `/login?callbackUrl=%2Fdashboard`
- [ ] **Unauthenticated API request:** `curl -s http://localhost:3001/api/user/providers` → `{"success":false,"errorCode":"UNAUTHORIZED","error":"Authentication required"}` (401)
- [ ] **Malformed session cookie (page):** `curl -sI -b "better-auth.session_token=garbage" http://localhost:3001/dashboard` → 200 (middleware passes; client-side JS handles redirect)
- [ ] **Malformed session cookie (API):** `curl -s -b "better-auth.session_token=garbage" http://localhost:3001/api/user/providers` → `{"error":"Unauthorized"}` (handler validates session)
- [ ] **Public paths bypass middleware:** `curl -sI http://localhost:3001/login` → 200 (not redirected)
- [ ] **Health endpoint unaffected:** `curl -s http://localhost:3001/api/health` → `{"success":true,...}`

## 5. Email Domain Restriction

- [ ] **Allowed domain:** Sign up with `user@tstc.edu` → succeeds
- [ ] **Disallowed domain:** Sign up with `user@evil.com` → `{"success":false,"error":"Registration is restricted to institutional email domains. Allowed: tstc.edu,coachingthegist.com"}`
- [ ] **Empty `ALLOWED_EMAIL_DOMAINS`:** If intentionally set to empty string, all domains should be accepted (test by temporarily clearing the var)

## 6. Password Reset

- [ ] **With RESEND_API_KEY:** `curl -s -X POST http://localhost:3001/api/auth/request-password-reset -H "Content-Type: application/json" -d '{"email":"admin@tstc.edu"}'` → logs `[Auth] Password reset requested for:` and `[Email] Sent to:` (or error details)
- [ ] **Without RESEND_API_KEY:** If key is removed, reset URL should appear in stdout logs: `[Auth] RESEND_API_KEY not set. Reset URL (expires in 1h):` followed by the URL
- [ ] **Reset email arrives:** Check inbox at the seeded admin email

## 7. Cross-Origin

- [ ] **Wrong origin:** `curl -s -H "Origin: https://evil.example.com" http://localhost:3001/api/auth/session` → should not return valid session data
- [ ] **Configured origin:** From the browser at `https://maic.coachingthegist.com`, login and session refresh should work normally

## 8. Docker Build Verification

After `docker compose up -d --build`:

- [ ] Container is healthy: `docker compose ps` shows `Up` and `curl http://localhost:3001/api/health` returns `{"success":true,...}`
- [ ] No `ERR_INVALID_URL` in build logs (indicates `NEXT_PUBLIC_APP_URL` was not available at build time)
- [ ] Theme toggle appears on all 8 pages (dashboard, catalog, enroll, settings, admin, bulk-provision, policy, usage)

## 9. Post-Deploy Smoke Test

- [ ] Login works from browser at `https://maic.coachingthegist.com/login`
- [ ] ThemeToggle shows on dashboard (sun/moon/monitor icon)
- [ ] ThemeToggle cycles: light → dark → system → light
- [ ] Auth-protected pages redirect to login when not authenticated
- [ ] Logout clears session and redirects to home
- [ ] Admin back button says "Dashboard" and navigates to `/dashboard` (not `/`)
- [ ] Settings back button goes to `/dashboard` (not `/`)
